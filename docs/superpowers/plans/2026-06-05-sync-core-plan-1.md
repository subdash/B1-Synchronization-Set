# Sync Core (Plan 1 of 2) Implementation Plan

> **For agentic workers:** This plan is a guided exercise. It describes WHAT to build, which Elixir/OTP concepts to use, the test cases to cover, struct shapes, and pseudocode — but **the human writes the code.** Do not write implementation or test code unless explicitly asked. See `CLAUDE.md` at the repo root. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the fully-tested, network-free correctness core of the replicated-folder sync system: version vectors, conflict resolution, the per-node replica state machine, a convergence property test, and a persisted Index store.

**Architecture:** A pure `Replica` state machine holds a map of `path → Entry` and exposes three operations (`local_write`, `local_delete`, `apply_remote`) plus a `merge`. All conflict/dominance/tombstone logic lives in pure functions over version vectors, so the hard distributed-systems correctness is testable with zero I/O. A `StreamData` property test gossips N in-memory replicas to a fixpoint and asserts identical convergence. The `Index` GenServer wraps the pure replica with DETS persistence for single-node durability.

**Tech Stack:** Elixir 1.20 / OTP 29, `:crypto` (SHA-256, built-in), `:dets` (persistence, built-in), `stream_data` (property testing, test-only).

**Scope note:** This is Plan 1 of 2. Plan 2 (Watcher, LocalChange, Control plane, DataPlane/TCP, Reconciler, Membership/libcluster, supervision wiring, multi-node integration tests) lives in `2026-06-05-sync-distribution-plan-2.md`.

**Spec:** `docs/superpowers/specs/2026-06-04-replicated-folder-sync-design.md`

**Design decision locked in here (refines the spec):** The deterministic conflict rule is **"larger checksum keeps the canonical name"** (a pure function of content, unambiguous even for multi-node vectors — cleaner than "lower node-id"), and the conflict filename is derived from the **losing checksum** (`name.sync-conflict-<short-checksum>.ext`) rather than a wall-clock timestamp, so every node generates the identical name. This is what makes conflict resolution converge.

**TDD rhythm for every task:** write the failing test(s) → run and watch them fail for the right reason → implement the minimum → run until green → commit. Commit messages end with the `Co-Authored-By` trailer per `CLAUDE.md`.

### Task 2: VersionVector (pure)

**Files:** `lib/sync_set/version_vector.ex`, `test/sync_set/version_vector_test.exs`.

**What you're building:** a version vector = `%{node_atom => non_neg_integer}`. The foundation of all conflict detection.

**Concepts/APIs:** plain maps; `Map.update/4` (increment), `Map.merge/3` with a `max` resolver, `Map.get/3`, `Enum.all?/2`. Property testing via `use ExUnitProperties`, `StreamData.map_of/2`, `StreamData.member_of/1`, `StreamData.integer/1`.

**Public functions:** `new/0`, `increment(vv, node)`, `merge(a, b)`, `compare(a, b)`.

**`compare/2` pseudocode** (returns `:equal | :dominates | :dominated | :concurrent`):
```
compare(a, b):
  a == b                              -> :equal
  covers?(a, b)                       -> :dominates   # a >= b in every component of b
  covers?(b, a)                       -> :dominated
  otherwise                           -> :concurrent

covers?(a, b): every {node, count} in b has Map.get(a, node, 0) >= count
```
(You only need to iterate `b`'s keys — keys present only in `a` can only make it larger.)

- [ ] **Step 1: Failing tests.** Example cases: equal vectors; dominance both directions (`%{a: 2, b: 1}` vs `%{a: 1, b: 1}`); concurrent (`%{a: 2}` vs `%{a: 1, b: 1}`); anything dominates `%{}`. Properties (use a generator over keys `[:a, :b, :c]`, counts `0..5`): merge commutative; merge idempotent; `compare(increment(a, n), a) == :dominates`; compare antisymmetric (dominates ⇄ dominated, equal/concurrent symmetric).
- [ ] **Step 2:** Run the test; confirm it fails (module undefined).
- [ ] **Step 3:** Implement the module.
- [ ] **Step 4:** Run until green.
- [ ] **Step 5:** Commit (`feat: version vector algebra with property tests`).

### Task 4: Entry struct and Conflict rules (pure)

**Files:** `lib/sync_set/entry.ex`, `lib/sync_set/conflict.ex`, `test/sync_set/conflict_test.exs`.

**Entry — the per-path metadata record.** Basic shape:
```
%SyncSet.Entry{
  vector:   %{},     # version vector
  checksum: nil,     # hex sha256, or nil for a tombstone
  size:     0,       # bytes (0 for a tombstone)
  deleted:  false    # true => tombstone
}
```
Use `defstruct` with those defaults plus a `@type t`.

**Conflict — the two deterministic rules.** Both must be pure functions of data every node already holds, so independent nodes converge without coordinating.
- `winner(left_entry, right_entry)` → `:left | :right`. Rule: the entry whose `checksum` is the lexicographically larger string keeps the canonical name (`left >= right -> :left`).
- `conflict_path(path, loser_checksum)` → the loser's new filename. Insert a `sync-conflict-<short>` segment (first 8 chars of the losing checksum) **before the extension**, preserving the directory. Use `Path.extname/1`, `Path.basename/2`, `Path.dirname/1`, `Path.join/2`.

Examples to anchor it: `conflict_path("notes.txt", "abcdef01...")` → `"notes.sync-conflict-abcdef01.txt"`; `"sub/dir/notes.txt"` → `"sub/dir/notes.sync-conflict-abcdef01.txt"`; `"README"` (no ext) → `"README.sync-conflict-abcdef01"`.

- [ ] **Step 1: Failing tests** for `winner/2` (larger checksum wins; order-independent) and `conflict_path/2` (the three examples above; identical output for identical input).
- [ ] **Step 2–4:** Fail → implement Entry + Conflict → green.
- [ ] **Step 5:** Commit (`feat: entry struct and deterministic conflict rules`).

### Task 5: Replica state machine (pure) — the heart

**Files:** `lib/sync_set/replica.ex`, `test/sync_set/replica_test.exs`.

**What you're building:** one node's view = `%Replica{node: atom, index: %{path => Entry}}`. All sync semantics live here as pure functions. No processes, no I/O.

**Concepts/APIs:** structs, pattern matching on `%Entry{}`, `Map.get/2`, `Enum.reduce/3`. Lean on the Task 2/4 modules (`VersionVector`, `Conflict`).

**Public functions:**
- `new(node)` → empty replica.
- `get(replica, path)` → `Entry | nil`.
- `local_write(replica, path, checksum, size)` — **bump the local component from the CURRENT entry's vector, including a tombstone** (this is the resurrection rule). New entry is live.
- `local_delete(replica, path)` — only on a live entry: write a tombstone with the local component bumped, `checksum: nil`. Absent / already-tombstoned → no-op (return replica unchanged).
- `apply_remote(replica, path, incoming_entry)` — fold in a remote entry (see pseudocode).
- `merge(into, other_replica)` — `Enum.reduce` over `other.index`, `apply_remote` each.

**`apply_remote` pseudocode:**
```
case current = index[path]:
  nil -> put(incoming)
  else case VersionVector.compare(incoming.vector, current.vector):
    :equal     -> unchanged
    :dominated -> unchanged          # we already have newer-or-equal
    :dominates -> put(incoming)      # covers normal updates, tombstones, resurrection
    :concurrent -> resolve(path, current, incoming)
```

**`resolve` pseudocode** (all branches deterministic & symmetric across nodes):
```
merged = VersionVector.merge(current.vector, incoming.vector)

both live:
  {win, lose} = by Conflict.winner(current, incoming)
  put(path, %{win | vector: merged})                 # winner keeps name, merged vector
  put(Conflict.conflict_path(path, lose.checksum), lose)   # loser preserved as conflict copy

both deleted:
  put(path, %{current | vector: merged})             # stays a tombstone

live vs delete (concurrent):
  live_one = whichever is not deleted
  put(path, %{live_one | vector: merged})            # the edit wins; no conflict copy
```
**Idempotency guard for the conflict copy:** when placing the loser at its conflict path, only overwrite if it dominates whatever (if anything) is already there — otherwise leave it. This keeps `apply_remote` idempotent.

- [ ] **Step 1: Failing tests.** Cover: `local_write` on fresh path → `%{node => 1}`; second `local_write` bumps to `2`; `local_delete` on live → tombstone with bumped vector; `local_delete` no-op on absent/already-deleted; `apply_remote` accepts a dominating entry; ignores a dominated one; applies a dominating tombstone; **live re-create dominating a tombstone resurrects**; **two concurrent live edits → both nodes' indexes end identical, larger-checksum keeps the name with merged vector, loser at the conflict path**; concurrent edit-vs-delete → live wins; `apply_remote` idempotent (apply same entry twice → unchanged).
- [ ] **Step 2:** Fail.
- [ ] **Step 3:** Implement. (Expect to iterate `resolve` against the convergence test in Task 6.)
- [ ] **Step 4:** Green.
- [ ] **Step 5:** Commit (`feat: pure replica state machine`).

### Task 6: Convergence property test (the crown jewel)

**Files:** `test/sync_set/convergence_test.exs`.

**What you're building:** the definitive eventual-consistency test. Generate a random op sequence across N in-memory replicas, gossip to a fixpoint, assert all indexes identical.

**Concepts/APIs:** `use ExUnitProperties`; `StreamData` combinators (`member_of`, `one_of`, `tuple`, `constant`, `binary/1` with `min_length`/`max_length`, `list_of/2`); `check all ... do`; `Enum.map`, `Enum.uniq`, recursion with a round cap.

**Shape of the test:**
```
nodes = [:a, :b, :c]; paths = ["f1.txt", "f2.txt", "f3.txt"]

op generator -> {origin_node, path, {:write, content} | :delete}

property:
  start one Replica per node
  reduce ops: apply each to its ORIGIN replica (local_write/local_delete)
  gossip_to_fixpoint(replicas)        # see below
  assert all replicas' .index are equal (Enum.uniq length == 1)

gossip_to_fixpoint(replicas, rounds \\ 10):
  rounds == 0 -> return                # cap, so a bug fails the assertion, not hangs
  next = each replica merges every replica into itself (Replica.merge)
  indexes unchanged? -> return next; else recurse rounds-1
```
Why iterate rounds: conflict resolution can create NEW entries (conflict copies) that must themselves propagate.

- [ ] **Step 1:** Write the property test.
- [ ] **Step 2:** Run it. If it fails, `stream_data` prints the minimal shrunk op sequence that broke convergence — that's a **real bug in `Replica`**, not the test. Use the systematic-debugging skill; do **not** weaken the assertion.
- [ ] **Step 3:** Run `mix test` (whole suite green).
- [ ] **Step 4:** Commit (`test: convergence property test across gossiping replicas`).

### Task 7: Index store (GenServer + DETS persistence)

**Files:** `lib/sync_set/index.ex`, `test/sync_set/index_test.exs`.

**What you're building:** a stateful, single-node wrapper around `Replica` that persists every change to DETS and reloads it on restart. Plan 2's networking calls into this.

**Concepts/APIs:** `use GenServer`; client/server split; `GenServer.start_link/3` with a `:name`; `GenServer.call/2`; `init/1` returning `{:ok, state}`; `handle_call/3`; `terminate/2`; `Process.flag(:trap_exit, true)` so `terminate` runs to close DETS. DETS: `:dets.open_file(table, file: charlist_path, type: :set)`, `:dets.insert/2`, `:dets.foldl/3`, `:dets.sync/1`, `:dets.close/1`. In tests: `start_supervised!/1` / `start_supervised!/2`, `stop_supervised/1`, `System.unique_integer([:positive])`, `System.tmp_dir!/0`, `on_exit/1`.

**Options to accept:** `:node` (default `Node.self()`), `:dets_path`, `:table` (default `:sync_set_index`), `:name` (default the module).

**State shape:** `%{replica: %Replica{}, table: dets_table}`.

**Public API (thin pass-throughs to the replica, persisting after each change):** `get/2`, `snapshot/1` (returns the index map), `local_write/4`, `local_delete/2`, `apply_remote/3`. The three mutators reply `:ok`.

**Persistence approach:** on `init`, open DETS and `:dets.foldl` all `{path, entry}` rows into the replica's index. On each mutation, apply the pure replica function, then write only the changed paths back (`:dets.insert` where `before[path] != after[path]`), then `:dets.sync`.

- [ ] **Step 1: Failing tests** (each with an isolated temp DETS file + unique table/process name via `setup`): `local_write` then `get` → bumped vector; `snapshot` returns all paths; `local_delete` → tombstone; `apply_remote` folds a remote entry; **state persists across restart** (write, `stop_supervised`, restart against the same file, entry still present).
- [ ] **Step 2–4:** Fail → implement → green; then run full `mix test`.
- [ ] **Step 5:** Commit (`feat: durable Index store over Replica with DETS persistence`).
